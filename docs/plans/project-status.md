# Miva Buddy Web — Current Project Status

**Updated:** 2026-10-14. **Release status:** Development prototype; no public deployment has occurred. The first public deployment is the V1 release milestone. Internal phases and milestones are development stages, not product versions.

## Google-auth beta work (local implementation)

- Replaced the anonymous-first entry flow in local code with Google OAuth through Supabase Auth PKCE. The callback exchanges the code server-side, verifies an explicit non-anonymous Auth identity, and routes by profile completion. Protected pages, server actions, and API routes use the shared permanent-user guard; sign-out is local-session scoped.
- Migrations 0000–0013 are applied and verified on the approved hosted Miva Buddy (Website) project. Migration 0011 enforces permanent-user access for owner-scoped application tables; the three existing `course-materials` Storage policies were updated separately through the Supabase Dashboard to add the permanent-user condition while retaining their bucket and ownership restrictions. Existing anonymous test accounts/data were not migrated, linked, or deleted.
- User-verified on the local Supabase stack: Google OAuth sign-in works; signing out and back in with the same Google account preserves the student's profile and Learn conversations. Migration 0011 was applied locally, and a read-only check confirmed 12 restrictive RLS policies plus retrieval RPC grants of `anon=false` and `authenticated=true`. These are local checks only, not hosted-project verification.
- Local Supabase config disables anonymous sign-ins and email-provider signup and enables Google using environment-variable references. Production Google OAuth credentials, provider settings, callback/redirect allowlists, and hosted sign-in flows still require final verification. The live two-user isolation test is still unverified; the disposable test harness is retained but intentionally postponed. Do not claim auth readiness until hosted setup and controlled isolation checks are complete.
- Legacy hosted browser tests still create anonymous identities; they must not be treated as Google-auth coverage. The local Google test used the configured local Supabase and Google OAuth setup; no hosted credentials were added or used.

## Deployment blockers

- The selected $0 hackathon demo target is one Render Free web service with the Next server and bundled PDF worker supervised together via `npm run start:render-demo`. The launcher is local code only; no Render service has been created or verified. This sleeping, resource-constrained co-location is not suitable as a reliability promise for public production. A persistent separately supervised worker remains the production target.
- Migrations 0000–0013 are applied and verified on the approved Miva Buddy (Website) project, and the three existing `course-materials` Storage policies were updated and verified separately. Render deployment and production smoke testing remain pending; complete Google OAuth/Auth configuration, managed secrets, Gemini account quota/data-use review, recovery planning, and hosted application-flow checks before public launch.
- Before using Gemini embeddings with hosted student data, review the selected account's current quota and data-use terms and perform a controlled production smoke test after Render is configured. Existing materials with vectors from another model space must be reprocessed before relying on Gemini retrieval; do not compare vectors across model spaces. The Render demo topology bundles web and worker into one sleeping, resource-constrained Free service and is a hackathon compromise, not an independently reliable production worker runtime.
- Establish backups/recovery, monitoring, provider budgets/quotas, retention/deletion, and incident-response operations.
- Keep M7/M8 source approval and excerpt-backed evidence gates closed unless their specific permissions and acceptance criteria are satisfied.
- The full development dependency audit has unresolved `braces` (high) and legacy nested `esbuild` (moderate) advisories; production dependency audit was clean in the recorded M9 snapshot. Recheck before release.
