## Important approved decisions

- The modular-monolith architecture and milestone implementation plan are approved.
- Local development supports Ollama; Gemini is the provisional hosted M2 provider, with Groq retained as an alternate. Both exact handoff Gemini model IDs passed the current live Miva Buddy structured contract, though long-answer latency and intermittent earlier errors remain limitations. Provider/model suitability requires passing Miva Buddy's actual structured response contracts, not merely endpoint or prose success.
- Relevant minimized course excerpts may be sent to configured hosted providers.
- The prototype targets zero or very low operating cost without weakening trust or security boundaries.
- Nigerian and global job postings are eligible evidence; geography is a ranking signal, not a truth condition.
- No job-posting source is approved yet. Milestone 7 is a required legal and technical evaluation gate.
- Product decision: MVP has no student-facing email/password authentication, verification, password reset, SMTP, or cross-device restoration. Supabase anonymous Auth establishes an internal stable UUID when onboarding is submitted; same-browser persistence and RLS isolation remain required.
- Supabase anonymous Auth is preferred over a custom browser-managed session because its signed session and `auth.uid()` integrate with RLS without custom token/authorization infrastructure.
- Milestone 1 now implements direct onboarding, anonymous identity creation on profile submit, a Drizzle profile schema with RLS policies, and the persistent workspace shell. Hosted identity, persistence, profile update, and isolation behavior are verified.
- Milestone 4 persists course/material/concept context separately from Direct Learn. The security-invoker retrieval RPC is `authenticated`-only, and source presentation resolves solely from owner-scoped stored metadata. Gemini remains a replaceable adapter; M4 live evaluation used synthetic course excerpts only. The deterministic lexical-overlap filter is not a semantic entailment proof.
- Milestone 6 stores Practice messages in owner-scoped `practice_messages`; RLS allows authenticated owner SELECT/INSERT only. Mode-specific structured schemas omit stronger fields, the server derives mode from the owned session, and accepted answers are validated before persistence. Gemini receives curated title/difficulty/tags, student-supplied content, and mode-filtered accepted history—not LeetCode statements or telemetry. Hands Off uses conservative lexical checks; these are not semantic proof. M6 evaluation used Gemini `models/gemini-3.5-flash-lite` and synthetic-only prompts.
- Verified project commands: `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build`. `npm run test:e2e` runs local first-visit, accessibility, and responsive checks by default; hosted Auth integration tests require `RUN_HOSTED_SUPABASE_TESTS=1` and are rate-limited by Supabase.

## M2 implementation decisions

- Direct Learn is explicitly general and ungrounded; no materials, retrieval, or citations enter this route.
- Only the current message and up to seven prior messages (eight total, capped at 12,000 characters) are selected for provider context. Requests are capped at 2,000 characters, bodies at 16 KiB, and authenticated users at 8 messages per minute.
- The app persists the question before provider execution so a provider outage does not discard it. Provider names, raw errors, and credentials are not shown to students.
- Gemini is the provisional hosted adapter for M2; it has a server-only provider implementation, mocked contract tests, and passing live synthetic structured-output evaluations for both exact IDs. Its ~38–40 second introductory-answer latency and intermittent earlier errors remain concerns; cost was not measured. Groq remains a replaceable alternate; Ollama remains the local option. Decision details: `docs/engineering/ai-provider-decision.md`.
- User reports applying the Learn SQL migration; read-only REST checks confirmed both table names exist and direct anonymous access is denied. Hosted browser tests used only synthetic Learn records and verified owner-scoped reads/writes.
- Gemini hosted evaluation sent synthetic prompts only and did not contact Supabase. The evaluation uses the ignored local key; no credential is committed. Exact setup and test commands are in `docs/engineering/milestone-2-setup.md`.
